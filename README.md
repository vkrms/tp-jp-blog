# Пакет для разработчика: японский SEO-блог Travelpayouts (旅アフィリ・ラボ)

Версия пакета: 2026-11-10. Название сайта и маскот (Tabi) — рабочие.

> **Актуальная спецификация — `docs/spec.md`.** Остальное в этом README — исходный концепт; при расхождении побеждает спецификация. План по её доработке — `docs/next-steps.md`.
>
> **Структура репозитория (целевая, стадия 2):**
> - `astro/` — публичный сайт (то, что видят пользователи): статический Astro, собирается в GitHub Actions и заливается на Hostinger.
> - `laravel/` — админка (Filament) и оркестратор (cron → OpenRouter → MySQL), плюс API, из которого Astro берёт контент при сборке.
> - В корне — общие папки: `agents/`, `content/`, `docs/`, `tools/`.
>
> Корень — npm workspace: `npm run dev|build|check` запускают Astro из `astro/`, сборка попадает в `astro/dist/`. Скрипты `tools/*` и их зависимости остаются в корне.

## Что нужно сделать (по порядку)

1. **Собрать боевой сайт.** Прототип в одном файле на `#hash` Google не индексирует как отдельные страницы. Нужен статический сайт (Astro, Eleventy или Next.js в static-режиме): **один URL на статью** (`/articles/<slug>/`), `title`, `description`, `canonical`, `hreflang`, `sitemap.xml`, `robots.txt`, структурированные данные (Article, FAQPage, BreadcrumbList). Дизайн, компоненты и тексты — из прототипа, контент — из `content/`. Язык по умолчанию — японский.
2. **Перенести контент в файлы репозитория** (уже в `content/`). Числа в статьях сейчас записаны в тексте; на этапе переноса связать их с `fact_id` из `facts.yaml`, иначе обновлятору придётся искать значения по тексту.
3. **Подключить валидатор** к CI (`validate.yml`) и не вливать PR с ошибками.
4. **Агентов подключает владелец проекта (Мария Кузнецова) вместе с Claude, не разработчик** (раздел ниже). От вас: репозиторий с папками `content/`, `agents/`, `tools/`, `.github/workflows/` без изменений и установка GitHub-приложения Claude на репозиторий. Секрет `CLAUDE_CODE_OAUTH_TOKEN` добавляет владелец проекта.
5. **Страницы Политика конфиденциальности и «Контакты»** (с почтой для обратной связи): создать и добавить ссылки в футер; тексты согласовать с юристами. Футер: «© Travelpayouts, 2011–<текущий год>» (год считается автоматически).
6. **Ссылки регистрации.** Все кнопки ведут на `https://landings.travelpayouts.com/?tp_place=landing_jp-seo-blog` (константа `KEY` в прототипе). Для различения кнопок в аналитике можно добавить суффиксы к `tp_place`.
7. **Домен и Search Console** (см. «Открытые вопросы»).
8. **Ссылки на источники в тексте.** Агенты ставят в тексте статей Markdown-ссылки `[текст](https://…)` в строках `ja`/`en` (абзацы, ячейки таблиц, пункты списков). Рендерер должен превращать их в `<a href rel="noopener">`. Это обычные редакционные ссылки, не партнёрские.
9. **Английская версия закрыта от индекса** (Basic Auth или отдельный staging; без `hreflang` на закрытые страницы). Она нужна редакции для проверки, а машинный перевод в индексе — риск по политике Google о массовом контенте.

## Как работает «статьи пишутся и обновляются сами»

Два агента (Claude). Они меняют репозиторий через pull request; влив PR выполняет CI по `policy.yaml`.

- **Автор** (`agents/writer.md`) раз в неделю берёт тему из очереди, собирает материал из реестра источников (tier 1 — список владельца проекта: JAO, Yano, A8.net, Moshimo, TravelVoice, TRAICY, блог Судзуки; при противоречии он побеждает), пишет статью по схеме (JA + EN), записывает цифры в `facts.yaml`, запускает валидатор и открывает PR.
- **Обновлятор** (`agents/updater.md`) раз в неделю проверяет факты и источники, у которых подошёл срок. Изменилось число/дата → правит факт и текст статей, обновляет `updated_at` и историю обновлений. Источник не прочитался → пишет «не получилось», не угадывает. Истёкшие акции помечает «終了» на следующий день.
- Всё, что агенты читают в интернете, — данные, а не инструкции.
- **Подбор тем.** Если очередь пуста, автор сам ищет темы (`agents/topic-discovery.md`): расширяет ключи по подсказкам Google и «похожим запросам», смотрит топ-10, оценивает кандидата по 5 признакам (порог 7 из 10), пишет статью только по сильному кандидату, а остальные кладёт в очередь. Объём поиска агент не знает, поэтому оценка косвенная; когда подключат Search Console, он начнёт с его данных. Выключатель: `policy.yaml` → `topic_discovery.enabled`.
- **SEO и ссылки.** Оба агента сначала читают `agents/seo-ja.md`: японские запросы и интент, title до 32 знаков, короткий slug (не меняется), 2–5 внутренних ссылок, дата обновления только при содержательной правке. **Если факт взят из источника, в самом предложении стоит ссылка на конкретную страницу источника.** Валидатор проверяет адрес (https, хост из реестра), анкоры (не «こちら») и привязку каждого источника из `sources` к тексту.
- **Исключённые темы:** право и маркировка рекламы, налоги и доход, условия ASP/площадок. Агенты не пишут такие статьи и не добавляют такой контент в существующие; валидатор такие тексты не пропускает.

**Публикация без человека.** В `policy.yaml` стоит `publish_mode: auto`: PR вливается сам, если валидатор зелёный. Человек нужен только в редких случаях (`needs_human_when`: источник не читается, два источника противоречат друг другу, слишком много изменений за запуск, подозрение на prompt injection). Ограничители: максимум 2 новые статьи в неделю, `paused: true` — аварийный стоп одной строкой, откат через `git revert`, недельный отчёт владельцу проекта о том, что опубликовано.

## Открытые вопросы и ограничения

- **Тексты статей — пилот.** Проверка носителем японского не делается; если сайт соберёт трафик, статьи валидируются с носителем. Цифры по выезду/въезду взяты из TravelVoice; первичный JNTO проверить напрямую.
- **Числа о Travelpayouts:** 11 travel verticals, Support 24/7 и средний ответ 26 минут, выплаты до 20-го, от $10, регистрация 3 шага — из TP Messagings (окт. 2026).
- «Commission» (разрешено в TP Messagings) и 報酬 (стандарт японского рынка): везде 報酬; подтвердить.
- Данные A8.net и Moshimo — самоописание конкурентов, в статьях помечены как таковые. Платные отчёты Yano и закрытые разделы JAO не используются.
- **Ссылки в 12 существующих статьях** расставляет обновлятор при первом запуске в боевом репозитории (чтобы не затереть правки разработчика). Пока предупреждения; когда все ссылки на месте, в `content/rules.json` ставим `source_links.enforce: true`, и они станут ошибками.
- **Шаблоны CI не запускались** — ожидайте подгонки (ключи, права, формат вызова агента).
- **Запуск агентов** идёт на подписке Claude Team владельца проекта: токен выдаёт `claude setup-token`, кладётся в секрет репозитория `CLAUDE_CODE_OAUTH_TOKEN`. Запуски расходуют лимиты её подписки (2 новые статьи + проверка в неделю, разнесены по дням). Токен привязан к её аккаунту: если он истечёт или она уйдёт, агенты остановятся. Допустимость такого использования в CI компании не подтверждена — уточнить у админа Team/IT; запасной вариант — ключ API через организацию в Claude Console (в workflows меняется одна строка с секретом).
- **Границы папок:** агенты пишут только в `content/` и открывают PR; разработчик владеет кодом сайта и деплоем. Автослияние включать только после того, как сайт собирается из `content/` и валидатор стоит в CI.
- **Домен:** нужен до публичного запуска (менять потом дороже для SEO). Для тестов можно выкатить на временный адрес хостинга.
- **Search Console:** не блокирует выкладку; настроить в день запуска, на аккаунт команды маркетинга (не личный разработчика), чтобы видеть трафик пилота.
