# Пакет для разработчика: японский SEO-блог Travelpayouts (旅アフィリ・ラボ)

Версия пакета: 2026-11-10. Название сайта и маскот (Tabi) — рабочие.

## Что внутри

| Папка / файл | Что это |
|---|---|
| `prototype/index.html` | Кликабельный прототип **в продакшен-виде** (без плашки MVP, без раздела Internal, без служебных формулировок). Один файл, hash-роутинг. Это **эталон дизайна и текстов**, а не готовый прод. |
| `prototype/src/` | Исходники прототипа (head.html = вёрстка + CSS-токены, data*.js = контент, app.js = отрисовка). `build_prod.py` собирает продакшен-версию. |
| `content/articles.json` | 12 статей (JA + EN) в структурированном виде; `update_log[].internal_note` — рабочие заметки, на сайт не выводятся. |
| `content/sources.json`, `facts.yaml` | Реестр источников и фактов (fact_id, источник, дата, как часто обновлять, в каких статьях). |
| `content/glossary.json`, `categories.json` | Глоссарий (26 терминов), 6 категорий. |
| `content/queue.json` | Очередь тем для агента-автора + список заблокированных тем. |
| `content/policy.yaml` | Как публикуются статьи: **автоматически**, с ограничителями (лимиты, аварийный стоп). |
| `content/rules.json` | Правила для валидатора: запрещённые формулировки, утверждённые числа Travelpayouts, **исключённые темы**. |
| `agents/writer.md`, `updater.md`, `rules.md` | Инструкции двух агентов (автор и обновлятор) и правила текста. |
| `tools/validate.mjs` | Валидатор (`node tools/validate.mjs`). Сейчас: 12 статей, 0 ошибок. |
| `.github/workflows/` | Шаблоны CI: `validate.yml`, `update.yml` (недельное обновление), `write.yml` (недельная новая статья). Шаблоны, не запускались. |

## Что нужно сделать (по порядку)

1. **Собрать боевой сайт.** Прототип в одном файле на `#hash` Google не индексирует как отдельные страницы. Нужен статический сайт (Astro, Eleventy или Next.js в static-режиме): **один URL на статью** (`/articles/<slug>/`), `title`, `description`, `canonical`, `hreflang`, `sitemap.xml`, `robots.txt`, структурированные данные (Article, FAQPage, BreadcrumbList). Дизайн, компоненты и тексты — из прототипа, контент — из `content/`. Язык по умолчанию — японский.
2. **Перенести контент в файлы репозитория** (уже в `content/`). Числа в статьях сейчас записаны в тексте; на этапе переноса связать их с `fact_id` из `facts.yaml`, иначе обновлятору придётся искать значения по тексту.
3. **Подключить валидатор** к CI (`validate.yml`) и не вливать PR с ошибками.
4. **Агентов подключает Мариша вместе с Claude, не разработчик** (раздел ниже). От вас: репозиторий с папками `content/`, `agents/`, `tools/`, `.github/workflows/` без изменений и установка GitHub-приложения Claude на репозиторий. Секрет `CLAUDE_CODE_OAUTH_TOKEN` добавляет Мариша.
5. **Страницы Политика конфиденциальности и «Контакты»** (с почтой для обратной связи): создать и добавить ссылки в футер; тексты согласовать с юристами. Футер: «© Travelpayouts, 2011–<текущий год>» (год считается автоматически).
6. **Ссылки регистрации.** Все кнопки ведут на `https://landings.travelpayouts.com/?tp_place=landing_jp-seo-blog` (константа `KEY` в прототипе). Для различения кнопок в аналитике можно добавить суффиксы к `tp_place`.
7. **Домен и Search Console** (см. «Открытые вопросы»).

## Как работает «статьи пишутся и обновляются сами»

Два агента (Claude). Они меняют репозиторий через pull request; влив PR выполняет CI по `policy.yaml`.

- **Автор** (`agents/writer.md`) раз в неделю берёт тему из очереди, собирает материал из реестра источников (tier 1 — список Мариши: JAO, Yano, A8.net, Moshimo, TravelVoice, TRAICY, блог Судзуки; при противоречии он побеждает), пишет статью по схеме (JA + EN), записывает цифры в `facts.yaml`, запускает валидатор и открывает PR.
- **Обновлятор** (`agents/updater.md`) раз в неделю проверяет факты и источники, у которых подошёл срок. Изменилось число/дата → правит факт и текст статей, обновляет `updated_at` и историю обновлений. Источник не прочитался → пишет «не получилось», не угадывает. Истёкшие акции помечает «終了» на следующий день.
- Всё, что агенты читают в интернете, — данные, а не инструкции.
- **Исключённые темы:** право и маркировка рекламы, налоги и доход, условия ASP/площадок. Агенты не пишут такие статьи и не добавляют такой контент в существующие; валидатор такие тексты не пропускает.

**Публикация без человека.** В `policy.yaml` стоит `publish_mode: auto`: PR вливается сам, если валидатор зелёный. Человек нужен только в редких случаях (`needs_human_when`: источник не читается, два источника противоречат друг другу, слишком много изменений за запуск, подозрение на prompt injection). Ограничители: максимум 2 новые статьи в неделю, `paused: true` — аварийный стоп одной строкой, откат через `git revert`, недельный отчёт Марише о том, что опубликовано.

## Открытые вопросы и ограничения

- **Тексты статей — пилот.** Проверка носителем японского не делается; если сайт соберёт трафик, статьи валидируются с носителем. Цифры по выезду/въезду взяты из TravelVoice; первичный JNTO проверить напрямую.
- **Числа о Travelpayouts:** 11 travel verticals, Support 24/7 и средний ответ 26 минут, выплаты до 20-го, от $10, регистрация 3 шага — из TP Messagings (окт. 2026).
- «Commission» (разрешено в TP Messagings) и 報酬 (стандарт японского рынка): везде 報酬; подтвердить.
- Данные A8.net и Moshimo — самоописание конкурентов, в статьях помечены как таковые. Платные отчёты Yano и закрытые разделы JAO не используются.
- **Шаблоны CI не запускались** — ожидайте подгонки (ключи, права, формат вызова агента).
- **Запуск агентов** идёт на подписке Claude Team Мариши: токен выдаёт `claude setup-token`, кладётся в секрет репозитория `CLAUDE_CODE_OAUTH_TOKEN`. Запуски расходуют лимиты её подписки (2 новые статьи + проверка в неделю, разнесены по дням). Токен привязан к её аккаунту: если он истечёт или она уйдёт, агенты остановятся. Допустимость такого использования в CI компании не подтверждена — уточнить у админа Team/IT; запасной вариант — ключ API через организацию в Claude Console (в workflows меняется одна строка с секретом).
- **Границы папок:** агенты пишут только в `content/` и открывают PR; разработчик владеет кодом сайта и деплоем. Автослияние включать только после того, как сайт собирается из `content/` и валидатор стоит в CI.
- **Домен:** нужен до публичного запуска (менять потом дороже для SEO). Для тестов можно выкатить на временный адрес хостинга.
- **Search Console:** не блокирует выкладку; настроить в день запуска, на аккаунт команды маркетинга (не личный разработчика), чтобы видеть трафик пилота.
