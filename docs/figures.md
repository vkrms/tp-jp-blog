# Спецификация: картинки внутри статьи (`figure`)

Версия: 1.0, 2026-11-26. Связанные документы: `docs/featured-images.md` (обложки),
`docs/spec-stage1.md` §3.2 (схема блоков), `agents/writer.md`, `agents/editor.md`.
Реестр шаблонов: `tools/figures/templates.json`. Валидатор: `tools/lib/figures.mjs`.

## 0. Решение (принято 2026-11-26)

Внутренние картинки делятся по тому, **где лежит истина**, а не по «стилю»:

| Что | Где цифры/текст | Как производится |
|---|---|---|
| Фото, редакционная иллюстрация с персонажем | в тексте статьи | растровая генерация (OpenRouter, как обложки) |
| Инфографика, схемы, шаги, псевдо-интерфейс, сравнения | **в картинке** | детерминированный HTML/SVG из `data`, не генерация |

Причины:

1. **Точность.** Почти весь смысл этих макетов — в тексте и числах (`21 Oct – 2 Dec`,
   `Fri 27 Nov`, `¥177,680`, `16:59`, `from Jan 2027 (partly Feb)`). Модель генерации
   искажает глифы и может молча поменять цену или дату. Это фактическая ошибка, которую
   нельзя проверить в JPEG, и она противоречит `agents/seo-ja.md` (alt/caption проходят фактчекинг).
2. **Двуязычие.** JA/EN из одного `data` — бесплатно; в растре пришлось бы генерировать
   две картинки и надеяться на орфографию.
3. **A11y и SEO.** HTML-фигура — это настоящий текст, а не картинка с текстом.
4. **Правки.** Исправление цифры — дифф в JSON, а не перегенерация.

Второе решение: **данные не живут только на картинке.** Если фигура показывает таблицу,
та же таблица (или `steps`/`list`) остаётся блочным текстом в статье. Фигура — визуальная
сводка, `caption` — вывод одной строкой. Валидатор предупреждает, если в статье есть
data-фигура, но нет ни одной таблицы/шагов.

Третье решение: **не растеризуем.** В статье фигура рендерится компонентом Astro.
Растр нужен только для обложек, OG и соцсетей (`tools/featured-image`), и тогда это
отдельный шаблон-экспорт, а не другой источник истины.

## 1. Категории (`kind`)

Валидируется только то, для чего есть шаблон: `kind` в блоке — это категория, которую
сайт реально умеет отрисовать сегодня.

| `kind` | Что это | Данные | Статус |
|---|---|---|---|
| `infographic` | карточки, сравнения, календарь, цифры | `data` | работает |
| `schematic` | шаги, поток, процесс, «лестница» | `data` | работает |
| `ui` | псевдо-интерфейс (карточка, билет, мок кабинета) | `data` | работает |
| `photo` | фото-сцена без текста в кадре | `src` + `brief` | план: фото в статье — блок `img` |
| `illustration` | редакционная иллюстрация с персонажем | `src` + `brief` | план: обложки и `img`, как сейчас |
| `composite` | растровая база + HTML-оверлей | `src` + `data` | план |

Плановые категории перечислены в `planned_kinds` реестра: валидатор отвечает на них
«пока не поддерживается», а не «шаблона нет». Растровые фигуры появятся вместе с полем
`src`, компонентом и шагом генерации; до этого фото внутри статьи — по-прежнему блок
`img` с `prompt_scene` (`docs/featured-images.md`). Это осознанно: двух способов сказать
«фото» в схеме быть не должно.

## 2. Схема блока

Новый блок с одним ключом (как остальные, `docs/spec-stage1.md` §3.2):

```json
{ "figure": {
  "kind": "infographic",
  "template": "check-cards",
  "data": { "items": [ { "label": ["公開前", "Before publishing"], "...": "..." } ] },
  "caption": ["タイミングごとの確認事項", "What to check at each stage"],
  "facts": ["f_20261109_sales"]
} }
```

| Поле | Обяз. | Смысл |
|---|---|---|
| `kind` | да | категория из §1; должен совпадать с `kind` шаблона в реестре |
| `template` | да | id шаблона из `tools/figures/templates.json` |
| `data` | да | структура, которую задаёт шаблон (см. §3); все значения — факты из статьи/`facts.yaml` |
| `caption` | да (шаблоны требуют) | вывод одной строкой, ja+en; рендерится в `<figcaption>` |
| `facts` | нет | id фактов из `content/facts.yaml`, на которых стоит фигура |

`alt` и `brief` появятся вместе с растровыми категориями; сегодня валидатор отвергает их
как неизвестные поля, чтобы в данных не копился неиспользуемый текст.

Неизвестный ключ шаблона или поля `figure` — ошибка валидатора (чтобы опечатка не
превратилась в пустую картинку). Неизвестный `template` ломает сборку Astro
(`requireTemplate()` бросает исключение).

## 3. Реестр шаблонов

`tools/figures/templates.json` — единственный источник id и требований к `data`.
Его читают и Astro (`astro/src/data/figures.ts`), и валидатор (`tools/lib/figures.mjs`).

Реализованы (слайсы из макета 2026-11-26):

| `template` | `kind` | `data` | Макет |
|---|---|---|---|
| `check-cards` | infographic | `items[] {label, body, source?}` | «What to check, and when» |
| `steps-arrow` | schematic | `items[] {title}` | «4 steps for a sale article» |
| `compare-pairs` | infographic | `pairs[] {avoid, prefer}` | «Write prices with conditions» |
| `timeline-gantt` | infographic | `rows[] {label, from, to?, when?, note?}, note?` | «Sales calendar to year-end» |
| `stair-steps` | schematic | `items[] {title}` | «6 steps» — восходящая лестница |
| `path-milestones` | schematic | `items[] {title}` | «6 steps» — пунктирная тропа с пинами |
| `balance-scale` | infographic | `cost/reward/net {label, value}, note?` | «Ad spend vs reward» |
| `ticket-stub` | ui | `{from, to, cabin, price, tag?, note?}` | посадочный талон |
| `stacked-cards` | infographic | `items[] {title}` | «6 steps» — стопка карточек |

`steps-arrow`, `stair-steps`, `path-milestones` и `stacked-cards` — одна и та же схема
`items[] {title}`, четыре оболочки; какую ставить, решает автор фигуры (не хэш слага).
`steps-arrow` читается как процесс, `stair-steps` — как рост, `path-milestones` — как
дорога к цели, `stacked-cards` — как плотный список. Последний элемент в `stair-steps`
и `path-milestones` акцентный (цель).

`path-milestones`, `stacked-cards` и `ticket-stub` пока не использованы ни в одной статье:
нет текста, где метафора или `ui`-оболочка уместнее списка, а повторять соседний
`steps`-блок или таблицу нельзя. Это осознанно: шаблон в реестре не значит «фигура в статье».

Все слайды макета 2026-11-26 реализованы. Следующее направление — растровые категории
(`photo`, `illustration`, `composite`), им нужны `src`, компонент и шаг генерации (§9).

У `timeline-gantt` ось месяцев **выводится из данных**: от месяца самого раннего `from` до
месяца самого позднего `to`, без ручного списка месяцев. `from === to` — точка-веха;
нет `to` — полоса идёт до края оси и тускнеет (событие ещё не кончилось). `when` —
необязательная текстовая замена авто-подписи периода (когда источник говорит «с января»,
а не «с 1-го числа»), `note` у строки и у фигуры — уточнения словами.

Добавление шаблона: запись в `templates.json` + компонент в
`astro/src/components/figures/` + ветка в `DataFigure.astro`. `DataFigure` падает,
если шаблон есть в реестре, но компонента нет (защита от расхождения).

## 4. Рендер

- `BlockRenderer` → `DataFigure` → компонент шаблона; всё внутри `<figure class="dfig">`
  с `<figcaption>` из `caption`.
- Только токены (`astro/src/styles/article.css`, переменные из `tokens.css`): никаких
  цветов из макета (лаймовый/ярко-синий) — они не часть дизайн-системы сайта.
- Mobile-first: карточки в столбик; стрелки потока появляются только на широком экране
  (≥900px), на мобильном порядок задают номера.
- Списки в фигурах — `display: grid` на `li`, поэтому маркеры не рисуются (как у `.steps`).
- Текст внутри фигур проходит через `rich()`: экранирование, `**жирный**` → `<mark>`,
  ссылки на источники остаются ссылками.

## 5. Правила агентов

**Писатель** (`agents/writer.md`):

- решает, где нужна фигура, и выбирает `kind` + `template` из реестра;
- заполняет `data` **только значениями, которые уже есть в статье или в источниках**,
  с `facts` для прослеживаемости;
- для `photo`/`illustration` ставит блок `img` с `prompt_scene`, а не `figure` (растровые фигуры — план);
- не пишет промпты для data-фигур: там нечего генерировать;
- держит ритм: фигура — сводка, а не замена таблицы/шагов (блок с теми же данными остаётся
  в тексте; фигура может стоять перед ним как «сначала картинка, потом подробности»),
  две фигуры подряд не ставятся.

**Редактор** (`agents/editor.md`):

- проверяет, что `template` есть в реестре, `kind` совпадает, `data` полон;
- сверяет каждое число/дату в `data` со статьёй и источниками;
- требует `caption` (ja+en) у каждой фигуры: под фигурой должен быть вывод, а не только картинка;
- не даёт оставить данные только в картинке.

## 6. Валидация

`node tools/validate.mjs` и `node --test tools/*.test.mjs`:

- `kind` и `template` известны, `kind` совпадает с шаблоном;
- обязательные поля `data` на месте, типы верные (`text` = ja+en, `date` = `YYYY-MM-DD`);
- лишние поля `data` и `figure` — ошибка (опечатки);
- `min`/`max` на массивах (например, `check-cards` — 2–5 карточек);
- `range` шаблона: у `timeline-gantt` `to` не может быть раньше `from`;
- плановая категория (`photo`, `illustration`, `composite`, `ui`) — ошибка «пока не
  поддерживается»; неизвестные поля (`alt`, `brief`) — ошибка, а не игнор;
- предупреждение, если в статье есть data-фигура, но нет ни `table`, ни `steps`.

## 7. Миграция

Первый прогон — статья `content/articles.json` → `sales-calendar`, потому что её данные
и есть макет:

- `check-cards` — после вводного абзаца в секции «更新チェックリスト：タイミング別»,
  таблица с теми же четырьмя строками остаётся ниже;
- `steps-arrow` — в начале секции «セール記事の書き方と、期限が来たときの更新»,
  подробные `steps` остаются ниже;
- `compare-pairs` — в секции «価格と条件の見せ方», пары собраны из её же абзацев
  (KLM 177,680 / 11/9 16:59 / 3,690円・手数料別);
- `timeline-gantt` — после таблицы «年末にかけて追いたいテーマ», её же три строки;
- `stair-steps` — в конце секции «アフィリエイトの流れは5ステップ» статьи `what-is-affiliate`,
  как итог после абзаца; сам список шагов остаётся выше.

Блок `img` не трогаем: фото остаются `img`. `figure` — только для того, что раньше
пришлось бы рисовать с текстом внутри.

## 8. Риски

- **Дрейф реестра.** id шаблонов в JSON и ветки `DataFigure` могут разойтись — поэтому
  `requireTemplate`/`DataFigure` падают на сборке, а тест проверяет манифест.
- **Дубль текста.** Данные фигуры повторяют таблицу. Это осознанно: фигура — сводка,
  блок — детали. Но две фигуры подряд или фигура + таблица «слово в слово» — плохо;
  следит редактор.
- **Глифы в растре.** Для `photo`/`illustration` запрет текста остаётся жёстким
  (как в `docs/featured-images.md`: единственный разрешённый текст — вордмарк/подпись места).
- **Рост объёма.** Фигуры не считаются в `chars_ja` (они дублируют данные), но считаются
  визуальными блоками в `article-stats.mjs`.

## 9. Открытые вопросы

- Нужен ли экспорт фигур в WebP для OG/соцсетей (тот же HTML → скриншот) — решить,
  когда понадобится первая OG-картинка из фигуры (например, `ticket-stub`).
- Растровые категории (`photo`, `illustration`, `composite`) и `ui` вынесены в
  `planned_kinds`: нужны `src`, компонент и шаг генерации. После этого `img` мигрирует
  в `figure{kind:"photo"}`, и один из двух путей убирается.
- Считать ли `figure` в лимите `MAX_IMAGES` в `expand-article` — сейчас фигуры
  учитываются отдельно от фото.
